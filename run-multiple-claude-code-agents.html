How to run multiple Claude Code agents in parallel

Give every task its own git worktree. That is the whole technical answer, and it is one command. The rest of this page is about the part that actually costs you time, which is noticing which agent is waiting.

Written 16 October 2026, updated 17 October. Stars, licences and prices checked that day.

Start here: one worktree per task

$ git worktree add ../app-dark-mode -b dark-mode
Preparing worktree (new branch 'dark-mode')
HEAD is now at 4a1c9f2 Snooze survives a restart

Each agent gets its own checkout on its own branch. They cannot touch each other's files.

Skip this and two Claude Code sessions in one folder will share a working tree. They both edit the same files, both run the formatter, both commit. What you get is one diff with two half-finished ideas in it, and git never saw two versions so it has nothing to resolve. More on worktrees, including the empty node_modules problem.

Four ways to watch them

The CLI makes worktrees itself

Claude Code can create and work in a worktree for you. Cheapest possible fix, no other software. If two or three parallel tasks is all you want, stop here.

It tells you nothing, though. Each session is a terminal you have to look at, and a question sits unanswered until you switch to that tab.

tmux and a script

A worktree per task, a pane for each, an agent in every pane. Free and transparent.

Claude Squad packages this: a terminal UI managing one tmux session and one worktree per agent. AGPL-3.0, 8,613 stars, no telemetry. Its last commit was 20 August 2026, so it has been quiet for about two months.

Nick Khami's write-up is the best account of this workflow and why he ended up building a tool for it. It reached 156 points on Hacker News.

A desktop app

They all do the worktree part. They differ in what they show you when an agent stops: a grid of terminals, a board, a list, an inbox.

Cloud and background agents

Claude Code on the web and Codex's hosted runs take the work off your machine. Good for long self-contained tasks. Less good when you want to watch and redirect, which is most of the time while you are still learning what agents are good for.

How many can you actually run

Three limits, in the order you meet them.

Your attention goes first. This is the one that bites, and it is why this category of software exists at all. We have not measured where the ceiling sits and we are not going to repeat the number everyone else prints without a source.

Your plan's rate limits go next, and they depend on the tier and what the agents are doing.

Your machine goes last and is rarely the problem. Worktrees are cheap and agents spend most of their time waiting on a model.

What Agentbox does with this

Every task gets a worktree, a branch and an agent. They run in parallel. A row comes back when its agent finishes or gets stuck, and you answer, approve or close it. The terminal, the diff and recurring tasks are built in. It runs on the Claude Code or Codex plan you already pay for, with no server, no account and no API key.

Pick something else if you want a native Windows build (Orca, Emdash and Nimbalyst ship one), a company and a support contract (Conductor), the largest community (Orca again), or to stay in the terminal (Claude Squad).
