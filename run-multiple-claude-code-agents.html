How to run multiple Claude Code agents in parallel

Three Claude Code agents running against one repository finished in 17.1 seconds of wall clock, inside the 16.4 seconds a single agent took on its own question. In bare terminal panes, finding out which of the three had finished meant opening all three.

Written 16 October 2026, rewritten 23 October against Anthropic's own documentation. Every star count, licence and commit date below was read again that day, and the dates are the last commit on each default branch rather than the figure the API hands over.

One git command gives each agent its own folder

git worktree add makes a second folder on a new branch. It runs once per task.

$ git worktree add ../app-dark-mode -b dark-mode
Preparing worktree (new branch 'dark-mode')
HEAD is now at 4a1c9f2 Snooze survives a restart

Each agent then has its own folder and its own branch, and nothing one of them does reaches another. Twenty-two of the twenty-three tools below automate that step, the exception being Agent Farm, which keeps every agent in one folder and coordinates them with lock files instead. They differ in what they show when an agent stops.

Why two agents in one folder destroy each other

Two Claude Code sessions in one directory share a working tree, so they read the same files, write the same files, run the formatter over each other and commit on top of each other.

Git never sees two versions of anything, so no merge conflict is raised. What comes out is one diff containing two half-finished changes.

Every tool below fixes this the same way, by giving each agent a folder of its own.

The four ways people run agents in parallel themselves

The Claude Code CLI makes the worktree itself

Claude Code can make the worktree itself, under .claude/worktrees/<name> on a branch called worktree-<name>. For two or three tasks at a time that is the end of the problem, with nothing installed and nothing to maintain.

A tmux session and a shell script, maintained by hand

The setup is a worktree per task, a tmux pane for each and an agent in every pane, maintained by whoever built it.

Six lines will do it.

for task in dark-mode snooze-restart search-archive; do
  git worktree add "../app-$task" -b "$task"
  tmux new-window -n "$task" -c "../app-$task" \
    "claude 'work on $task, commit when the tests pass'"
done

Nothing in it reports which pane has stopped.

Claude Squad packages that loop as a terminal UI, managing one tmux session and one worktree per agent under AGPL-3.0 with no telemetry. Its last commit was 20 August 2026, which left it quiet for about two months.

Nick Khami wrote up a month of living this way before building a tool to escape it, and that write-up reached 156 points on Hacker News.

A desktop app that manages the worktrees for you

Every app in the table handles worktrees. What is left to choose between is a grid of terminals, a kanban board, a list and an inbox.

Cloud sessions, which keep running when the laptop shuts

Claude Code on the web and Codex's hosted runs move the work off the local machine. They suit a task that can be described completely, and get harder when one needs interrupting and redirecting halfway.

What actually limits how many agents run at once

Agents spend nearly all their time waiting on a model, so CPU is not the first limit. The run below put a Mac under a load average between 12 and 19 while three agents worked, which is not an idle machine, and still none of them slowed each other measurably.

The limit is attention. A terminal pane holding a finished agent looks exactly like one holding a working agent, so telling them apart means opening each one, and the agent that has been waiting twenty minutes for a yes is the one checked last.

Agent view answers exactly that, for the sessions it knows about. Four of its limits are worth knowing before leaning on it, and all four are Anthropic's own words. A session open in another terminal does not appear until it is backgrounded. Every prompt typed into agent view starts a new session rather than continuing one. Shutting the machine down stops the running sessions. And each session spends the subscription quota independently, so the docs say to read the limits before dispatching many at once.

What three agents at once actually cost, measured on one Mac

Each agent got its own worktree of a shallow clone of this repository. All of them started at the same moment under claude -p, each with one factual question about the code to answer. The harness recorded wall clock per agent and the machine's load average.

Agents at onceTotal wall clockMedian per agentFastestSlowestErrors
116.4 s16.4 s16.4 s16.4 s0
317.1 s11.8 s10.9 s17.1 s0

Three agents finished in 17.1 seconds of wall clock, and one agent took 16.4, with no errors and no rate limit in either run.

That is not a controlled comparison, and saying so is more useful than the headline it replaced. The three agents answered three different questions and the single agent answered a fourth, which is why the three have a median of 11.8 seconds against the single agent's 16.4. An agent cannot get faster because two others are running beside it, so the gap measures the questions rather than the parallelism. What the run does establish is the ceiling, since three agents at once finished inside the time one agent took, and no run has yet been done on a quiet machine with every agent asked the same question.

The tasks were small and read-only, so this measures what parallelism costs rather than how fast Claude writes code. The Mac carried a load average between 12 and 19 throughout. Six and ten agents remain untested.

Where each tool puts the worktrees it creates

No two of the tools agree on where the worktree folder should go, so the README of whichever one is running is the only reliable answer. Somebody who built a worktree cleaner to deal with it wrote on Hacker News on 15 October 2026 that Codex, Claude Code, Orca and Superset each put their worktrees somewhere different, which made them hard to find. That post drew one point and no replies, so this is one person's annoyance rather than a groundswell.

Agentbox uses the middle layout, .claude/worktrees/<task id>, with a branch of the same name, so every task does its work inside the repository it belongs to. The worktree guide covers cleanup and the empty node_modules that catches everyone once.

Questions about running several agents at once

Can you run multiple Claude Code agents at once?

Yes, once each one has its own directory, and Claude Code has settings for exactly this. claude --worktree <name> makes the directory, worktree.baseRef chooses what it branches from, and isolation: worktree in a subagent's frontmatter makes it permanent for that agent. In the desktop app the Worktree toggle is per session and off by default.

How many agents can I run?

Three ran with no measurable penalty. Past that is untested here, and the ceilings other pages print carry no source. Rate limits and human attention both give out before the machine does.

How do I run multiple agents in VS Code?

The extension does it on its own. Its sessions list sits in the Activity Bar, and Open in New Tab or Open in New Window runs several conversations at once, each resumable from history. Pairing that with claude --worktree gives each one its own checkout.

What is the best way to manage multiple Claude Code sessions?

Below three agents, tabs are fine. Above three, pick from the table of twenty-three.

Can I run multiple Claude Code accounts?

Several agents on one subscription is ordinary use. Several accounts to dodge the limits breaks Anthropic's terms, and nothing here helps with it.

Questions about git and safety

Is it safe to run several agents in worktrees at the same time?

Yes for files. Agents cannot reach into each other's checkouts. They do share the git object store, which git handles, and everything outside git, which it does not. A dev server on a fixed port is the collision people actually hit.

What happens when two agents want the same file?

Nothing. In separate worktrees they are different files on disk. The conflict waits until merge time and git treats it like any other two branches.

Worktree or just a branch?

A branch is enough for one thing at a time. Two things at once need two folders.

How do I clean up afterwards?

$ git worktree remove ../app-dark-mode
$ git worktree prune          # drop records whose folders are gone
$ git branch -d dark-mode     # the branch is separate

Removing a worktree never deletes its branch, so a tidy git worktree list can sit beside a git branch output thirty lines long. remove also refuses while the folder has uncommitted changes, and --force overrides it. Thirteen commands cover the whole lifecycle.

Questions about cost and limits

Do these tools cost extra on top of Claude Code?

Most of them are free and run on an existing Claude Code or Codex subscription. Conductor charges $50 a month for Pro, which buys agents running in its cloud. Anything that asks for an API key bills separately from that subscription.

Will I hit a rate limit?

Not at three. Ten depends on the subscription tier and on how hard each agent is working. A limit arrives as an API error inside the agent that hit it rather than as a crash.

Does running ten agents slow my machine down?

Barely. The agents are waiting, not computing. What it does cost is a fresh node_modules per worktree.

$ git worktree list | wc -l
       7
$ du -sh ../app-*/node_modules | tail -1
417M	../app-snooze/node_modules

Seven worktrees of a typical Node project is a few gigabytes of the same dependencies. On macOS a block-sharing copy avoids most of it.

Questions about watching and reviewing

How do I review what five agents did?

Five finished branches are five diffs to read, whatever tool produced them. The thing worth having is one that shows the diff in the same window.

Can I check on agents from my phone?

Anthropic gets there first. Claude Code runs at claude.ai/code in a mobile browser and in the Claude apps for iOS and Android, and Dispatch pushes a notification when a desktop session finishes or needs approval. Among the twenty-three, Orca ships iOS and Android, Nimbalyst an iOS companion, Superset an iOS app on its paid tier, and Conductor one on Pro. Agentbox has none of them.

Does a GUI actually help, or is the terminal fine?

Under three agents an app is overhead. Over three it pays for itself in tabs nobody has to open. Twenty-one front ends exist, in four shapes.

Which tool fits which need

What Agentbox does with worktrees and the inbox

Every task gets a worktree, a branch and an agent of its own, and when one finishes or gets stuck its row comes back to the top of the inbox to be answered, approved or closed. The terminal and the diff sit in the same window.

It runs Claude Code and Codex locally on an existing subscription, with no server in the middle, no account to make and no API key anywhere in it.

Where Agentbox loses

The first thing Agentbox loses to is Anthropic. The desktop app comes with the subscription, it is supported, and it will follow every change to Claude Code before anybody else can. Anyone who only runs Claude Code, on one machine, should try claude agents and the Code tab before installing anything from the table above, including this one.

Against the rest, Agentbox is four weeks old with 94 stars to Orca's 102,844. There is no native Windows build, where Orca, opcode, Emdash, Nimbalyst and three others ship one. There is no mobile app, where Orca ships two. And there is no company behind it, where Conductor sells somebody to call.
