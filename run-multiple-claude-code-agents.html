How to run multiple Claude Code agents in parallel

One agent per terminal works until about three. After that the problem stops being the agents and becomes you: which one is waiting, and whose edits just landed on top of whose.

Written 16 October 2026. Every version number and price below was checked that day.

The short answer

Give every task its own git worktree, so each agent has its own checkout and its own branch and cannot touch another one's files. Then pick how you want to watch them: the Claude Code CLI can make worktrees itself, tmux plus a shell script is the free hand-rolled route, and a desktop app does it for you and tells you which agent is stuck. The hard part is never starting the agents. It is noticing which of them needs an answer.

Why it goes wrong by default

Two Claude Code sessions in the same folder share one working tree. They will both edit the same files, both run the formatter, and both commit. You get conflicts that are not merge conflicts — they are two half-finished ideas interleaved in one diff, and neither agent knows the other exists.

So every workable answer below starts the same way: isolate the filesystem first. Everything else is a question of how much ceremony you want.

The four approaches

1. Claude Code's own worktree support

The CLI can create and work in a git worktree for you, which is the cheapest possible fix and needs no other software. It is the right starting point, and if two or three parallel tasks is all you ever want, you can stop reading here.

What it does not do is tell you anything. Each session is still a terminal you have to look at, and the moment one of them asks a question it sits there waiting until you happen to switch to that tab. That is the ceiling, and it is a low one — most people hit it between three and five agents, not because the machine struggles but because they stop being able to track them.

2. tmux and a script

Make a worktree per task, open a tmux pane for each, run an agent in every pane. Free, transparent, and entirely yours to maintain.

Claude Squad (smtg-ai/claude-squad, AGPL-3.0, 8,613 stars) is this idea packaged: a terminal UI that manages one tmux session and one worktree per agent. It is small and it carries no telemetry, which some people care about a lot. Worth knowing before you adopt it: its last commit to the default branch was 20 August 2026, so it has been quiet for roughly two months.

The honest limitation of the whole tmux family is the same as approach 1 — a pane that needs you looks exactly like a pane that does not, until you look at it.

3. A desktop app

The apps in this category all do the worktree-per-task part and then differ in what they show you: a grid of terminals, a kanban board, a list, or an inbox. What you are really choosing is the shape of the thing that tells you an agent is waiting.

This is the approach we build, so read the next section with that in mind, and read the table with the prices and licences in it.

4. Hand it to the cloud

Background and cloud agents — Claude Code on the web, Codex's hosted runs, and several hosted products — take the work off your machine entirely. Good when the task is long and self-contained, and when you do not mind the code leaving your laptop. Less good when you want to watch, interrupt and redirect, which is most of the time while you are still learning what an agent is good for.

Where Agentbox fits, and where it does not

Agentbox gives every task its own git worktree and its own agent, runs them in parallel, and then hands the work back as a row you answer like email — or as a board, which is how a lot of people use it. You only hear from the agents that finished or got stuck. A terminal, the diff and recurring tasks are built in. It runs Claude Code and Codex locally on the subscription you already pay for: no server, no account, no API key.

Pick something else if:

  • You are on Windows and want a native app. Our desktop build is macOS. You can run the whole thing in a browser with npx agentbox-app on any platform with Node 22, and Linux gets a launcher entry too — but if you want a real Windows application, Orca, Emdash and Nimbalyst all ship one and we do not.
  • You want a company behind it. Conductor is a funded company with a paid team plan. We are free software with a very short history.
  • You want the largest community. That is Orca, by a factor of a thousand in stars.
  • You want to stay in the terminal. Claude Squad is a few hundred lines of tmux wrangling and no telemetry. If that is the point for you, an Electron app is the wrong shape.
  • Two agents is your ceiling. Use the CLI's own worktree flag and save yourself an install.

How many can you actually run?

Three limits, in the order you meet them. Your attention goes first, usually between three and five agents in terminals — which is the entire reason this category of software exists. Your plan's rate limits go next, and they depend on which plan you are on and what the agents are doing, so we are not going to print a number we cannot stand behind. Your machine goes last and is rarely the problem: worktrees are cheap, and the agents spend most of their time waiting on a model.

The useful reframe is that running more agents is not the goal. Closing the loop on more of them is. An agent that finished an hour ago and has been waiting for a yes since then is not parallelism, it is a queue with you at the head of it.
